# Brief Output Skill

先给结论。只保留读者完成当前任务所需的信息。删除后若不影响理解、实施或必要验证，一律删除。

## 工作流程

1. **结论前置**：开门见山给出直接结论或操作结果。不写寒暄、引言和铺垫。
2. **评估必要性**：逐句检查信息价值。先判断能否删除，再做润色。无需保留的信息直接删除，不改写为其他形式。
3. **剔除冗余与修辞**：删除比喻、口号、假想争论、过度承诺、讨论过程以及未要求的延展建议。
4. **精炼结构与表格**：同一事实只定义一次。表格某列取值全部相同时，提炼为表前一句话说明，并删除该重复列。删除与正文或表格重复的括注、样例和总结。
5. **全文一致性复核**：用户指出一处冗余或风格问题时，检查全文同类问题。用户认可简洁稿后，后续修订保持同等信息密度，不补回已删说明。

## 表达与删减规则

- **语言规范**：使用短句、主动语态和固定术语。一句话只表达一个要点。不使用分号连接无关复合句。
- **保留核心事实**：保留真实例外条件、约束、错误处理、不确定性和结论强度。不通过删除关键事实制造虚假确定性。
- **明确区分状态**：严格区分现有系统行为、本次方案设计与已实施结果。
- **消除代词指代**：将“该方案”、“上文所述”等会话指代替换为可独立理解的对象名称、文件路径或链接。
- **设计文档边界**：
  - 只写本次必要设计。已有机制满足需求时，一句说明沿用并注明来源，不重复展开设计。
  - 源码与配置能解决的技术决策由设计直接确定，不列为业务待确认项。
  - 不因精简或审查新增通用防护、恢复机制、边缘场景和冗余验证。
  - 默认不附部署计划、测试方案、证据清单或分析报告，除非用户明确要求。

## AI 冗余模式与替换指南

| 冗余模式 | 表现特征 | 处理方式 |
|---|---|---|
| 铺垫与寒暄 | “总的来说”、“值得注意的是”、“在开始之前...” | 删除，直接陈述事实 |
| 虚假承诺与空话 | “后续将进一步完善并确保系统高可用稳健运行...” | 仅保留有依据的具体机制，无依据直接删除 |
| 模板空章节 | 章节下仅写“不涉及”或“无” | 删除整节（除非用户明确要求保留完整模板骨架） |
| 重复定义 | 表格定义字段后，正文再次逐一复述每一字段 | 保留权威表格或单处定义，删除重复复述 |
| 过程性元话语 | “经过上一轮审查分析，我们得出以下改动...” | 删除审查过程，直接陈述最终确定的技术事实 |

## 校验清单

完成输出前，逐项核对：

1. 核心结论是否位于第一句？
2. 是否已删除所有空泛引言、比喻和推销式修辞？
3. 所有技术事实是否仅定义一次，无前后重复复述？
4. 是否保留了真实的安全约束、边界条件与失败处理规则？
5. 全文同类冗余是否均已清除？
