# Publication Ready Docs Skill

生成可独立阅读的交付级工程文档。以第一性原理和真实代码/配置事实为依据，彻底删除过程性讨论、自我评价与推销修饰。

## 适用文档与内容范围

- **详细设计 / 技术方案**：目标、必要改动、职责划分、接口契约、状态流转规则和配置项。默认不附部署计划、测试方案、验收矩阵或风险清单，除非用户明确要求或实际改动确有需要。
- **运行手册 / 运维文档**：执行前置条件、操作步骤、回滚方式和灾难恢复机制。
- **测试与审计文档**：验证场景、预期结果、实测结果和必要凭据。独立审计、复盘报告与 ADR 保留必要权衡分析。

## 工作流程

1. **查验现有实现**：优先检查权威源码与配置文件。可沿用的机制仅说明沿用及来源，不重复设计。新增机制必须对应明确需求或已验证的实际风险。
2. **确定结构边界**：仅保留适用章节。直接删除空章节或仅写“不涉及”的章节。仅当用户明确要求保留完整模板骨架时，才保留标题并简写“不适用”。
3. **明确职责与状态**：写清主体、前置条件、动作和预期结果。严格区分现有系统行为、方案决策设计与已实现结果。
4. **常规技术决策收敛**：源码、配置或常规技术选型能解决的问题，由设计直接确定。只有真正缺失且影响方案成立的外部业务约定，才列为待确认项并明确责任方。
5. **执行删除与精炼**：先判断能否删除，再做润色。**删除后若不影响理解、实施或必要验证，一律删除。**
   - 删除讨论历史、审查过程、元话语、自我评价、假想争论和空泛承诺。
   - 每个事实只定义一次。删除与正文或表格重复的括注、样例、速查和总结。
   - 表格某列取值全部相同时，提取为表前一句话说明，并删除该列。
6. **全文复核与对齐**：核对技术语义、边界条件、职责分工、关键数值和不确定性。技术口径变更时，同步修改交付范围内的正文、表格、代码和前提条件。

## 表达与删减规范

- **文字规范**：短句、主动语态、一句话一个要点。中文严格借鉴 ASD-STE100 清晰表达原则（禁用分号连接复杂句、避免动词名词化、避免名词堆叠）。
- **真实禁止规则保留**：否定句不是删除依据。限制写入范围、事务失败后果、安全禁止规则（如“不得覆盖其他程序字段”）必须完整保留。
- **消除指代与占位**：用项目具体事实替换会话代词（“该方案”、“上文”），清除过期占位符。示例与参数必须来自明确设计决策，不为补齐文字新增无依据的机制。
- **密度保持**：用户指出一类问题时检查全文；用户认可简洁稿后，后续修订保持该信息密度，不补回已删除说明。

## 校验清单

交付文档前，逐项核对：

1. 文档是否可独立理解，无会话残留和外部代词？
2. 是否已基于代码和配置事实完成查验，消除无依据的推测？
3. 是否已删除所有空章节与仅写“不涉及”的无用段落？
4. 接口契约、状态变迁与安全禁止规则是否清晰完备？
5. 全文同类冗余是否已彻底清理，术语前后口径是否完全统一？
