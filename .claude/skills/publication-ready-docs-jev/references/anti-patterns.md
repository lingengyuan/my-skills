# 常见坏味道

仅在难以判断某段是否必要时使用。先执行主文档的删除判断，再决定是否改写。

| 表达 | 处理 |
|---|---|
| “不负责、不涉及、不影响”等范围排除或安抚 | 无必要信息时删除；涉及真实职责或兼容性约束时保留事实 |
| “需要注意、为了避免误解、值得强调” | 删除包装，保留必要规则 |
| “经过审查、上一轮、根据本次要求” | 删除生成过程，陈述项目的最终事实 |
| “完善、高可用、确保稳定” | 仅保留已有依据的机制或指标；无依据时删除，不补造设计 |
| “暂时、以后可能、原则上” | 保留真实阶段、条件或不确定性；删除未决想法，不擅自增加路线图 |
| 重复括注、总结、样例或模板空章节 | 删除重复内容；仅保留用户明确要求的结构 |

否定句不是删除依据。字段写入限制、事务失败后果及操作安全规则可以直接使用“不得”或“不”。
