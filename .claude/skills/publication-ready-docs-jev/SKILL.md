# Publication Ready Docs with Jev

生成可独立阅读的正式文档。只保留必要事实、设计决策和约束。

## 1. 确定文档边界

按用户请求选择内容，不套用完整章节清单。

| 文档 | 默认内容 |
|---|---|
| 设计方案、详细设计 | 目标、必要改动、职责、接口、状态规则和关键配置 |
| 实施计划、运行手册 | 操作步骤、执行条件及必要恢复方式 |
| 测试文档 | 必要场景、预期结果、实际结果和相关证据 |
| README、API 文档 | 使用方式或接口契约 |
| 审计、复盘、ADR | 保留其所需的证据、分析和决策依据 |

设计文档默认不附部署步骤、测试计划、验收矩阵、风险清单或证据清单。用户指定的模板和交付范围优先。

## 2. 只保留必要设计

- 先查现有实现。已有机制满足需求时，写明沿用及来源，不重新定义刷新、重跑、传输等流程。
- 新增机制须对应明确需求或有依据的实际风险。不要为假设的边缘场景扩大改动。
- 区分必要兼容性约束与泛泛的“不影响其他功能”。保留前者，删除后者。
- 正文写确定的规则。方案决策与现有行为分开表述，未实施的设计不得写成已完成结果。
- 常规技术决策由设计解决。源码、配置或合理技术选择能确定的事项，不交给业务方裁决。
- 真正缺失的业务条件或外部接口约定，才列为待确认项。只保留影响方案成立的事项，并注明实际责任方。

## 3. 写清规则

使用 ASD STE100 的表达原则：短句、主动语态、固定术语。一句话表达一个要点。流程写清条件、主体、动作和结果。

直接定义职责和行为。将“应防止覆盖，方式待确认”改为具体的文件命名或写入规则，前提是该规则有技术依据且属于本次范围。

保留真实的禁止规则、事务边界、失败后果和兼容性限制。不能为缩短文字而削弱它们。

示例、代码和参数取值须来自已确认来源或明确的设计决策。示例格式不能成为新增事实或机制的理由。

## 4. 控制验证范围

验证用于证明本次改动有效。按主流程和已确认风险保留必要检查。

- 设计文档通常只写设计规则。用户要求验收条件时，再写直接相关的通过标准。
- 不默认加入全量失败注入、逐项回归、输入快照、哈希值或长期证据留存。
- 沿用且未受改动影响的流程，不单独增加验收。
- 保留用户要求的验证与真实安全、数据或接口约束。不得用“简洁”删除必要验证。

## 5. 发布前清理

1. 核对技术事实、设计范围和决策归属。保留关键来源，删除无助于实施的源码讲解。
2. 先删后改。删除讨论历史、审查过程、元话语、自我评价、假想争论和无信息量提醒。
3. 合并重复。每个事实只保留一个定义，不在摘要、正文、风险表和验收中反复解释。
4. 检查可实施性。规则须有明确条件和动作；删去空泛承诺，解决本设计负责的技术问题。
5. 核对语义。保留关键事实、否定约束、条件、接口契约和不确定性。

用户指出一类问题时，检查全文。用户认可简洁稿后，后续修订不补回已删除的分析、冗余验证和范围外设计。

技术口径变更时，同步修改相关正文、表格、代码和前提条件。只维护用户要求交付的权威文档；其他源文件仅在属于交付范围时同步。

## 6. 按需读取参考

遇到难以判断的表达问题时，读取 [常见坏味道](references/anti-patterns.md) 或 [转换示例](references/transformations.md)。示例用于表达转换，不授权新增功能、配置、验证或交付物。

清理结果须让未参与讨论的工程师看懂目标、必要改动和实现规则。完整性按任务需要判断，不按章节数量判断。

## 7. Jev 预筛

Jev 是可选的表达预筛工具，不决定技术方案。用户要求 Jev 扫描，或长文档的重复判断需要辅助时，使用现有脚本：

```bash
python scripts/jev_doc_review.py <input.md> [--doc-type 详细设计]
```

需要环境变量 `TYPESAFE_API_KEY`。脚本输出 `<input>.review.md` 和 `<input>.review.json`，不直接修改原文。

脚本扫描过程语言、元话语、防御性表达、影响面安抚、信息密度、重复、占位和术语一致性。先按句子预筛，再对疑似重复内容做全文判断。概率阈值由脚本管理。

处理报告时遵守以下规则：

1. 结合源码、用户要求和本文规则复核建议。Jev 概率不能证明技术事实。
2. 表格和代码不在脚本逐句扫描范围内，按实际改动检查相关内容。
3. 保留真实约束及用户指定的模板结构。不机械删除否定句或低评分内容。
4. 用户只要求报告时，提交报告，确认后再修改。用户已授权修订时，直接完成授权范围内的修改。
5. 只有影响方案的业务歧义才请求确认。常规技术选择不因存在多种解法而默认转交用户。

Jev 报告用于本次处理。除用户要求外，不增加永久审查报告或其他交付物。
