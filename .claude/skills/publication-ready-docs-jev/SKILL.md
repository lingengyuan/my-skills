# Publication Ready Docs with Jev Skill

生成可独立阅读的交付级工程文档。结合 Jev 自动化语义分析与精炼规范，彻底消除过程性讨论、跨章节重复和推销修饰。

## 适用文档与内容范围

- **详细设计 / 技术方案**：目标、必要改动、职责划分、接口契约、状态流转规则和配置项。默认不附部署计划、测试方案、验收矩阵或风险清单，除非用户明确要求或实际改动确有需要。
- **运行手册 / 运维文档**：执行前置条件、操作步骤、回滚方式和灾难恢复机制。
- **测试与审计文档**：验证场景、预期结果、实测结果和必要凭据。独立审计、复盘报告与 ADR 保留必要权衡分析。

## 工作流程

1. **查验现有实现**：优先检查权威源码与配置文件。可沿用的机制仅说明沿用及来源，不重复设计。新增机制必须对应明确需求或已验证的实际风险。
2. **确定结构边界**：仅保留适用章节。直接删除空章节或仅写“不涉及”的章节。仅当用户明确要求保留完整模板骨架时，才保留标题并简写“不适用”。
3. **明确职责与状态**：写清主体、前置条件、动作和预期结果。严格区分现有系统行为、方案决策设计与已实现结果。
4. **常规技术决策收敛**：源码、配置或常规技术选型能解决的问题，由设计直接确定。只有真正缺失且影响方案成立的外部业务约定，才列为待确认项并明确责任方。
5. **执行精简草稿**：先判断能否删除，再做润色。删除讨论历史、审查过程、元话语、自我评价、假想争论和空泛承诺。每个事实只定义一次。
6. **运行 Jev 预审**：对形成的文档草稿执行 Jev 自动化冗余检测。
7. **综合复核与落改**：结合 Jev 报告建议与事实规则决定删、改、留。如已获授权修订，直接修改文档；若仅需审查，交付审查报告。

## Jev 自动化审查

在当前 Skill 目录下执行审查脚本：

```bash
python3 scripts/jev_doc_review.py <input.md> --doc-type 详细设计
```

环境依赖：
- 环境变量：`TYPESAFE_API_KEY`
- 依赖工具：Python 3.8+ 及脚本依赖
- 输出产物：`<input>.review.md` 与 `<input>.review.json`（脚本默认不修改原文）

### Jev 报告判定规则

- **建议删除项**：结合上下文核验。确属冗余或元话语的句子直接删除。
- **建议保留项**：仍需按精简原则核对。若句子属于空泛承诺或无依据推测，即使 Jev 建议保留亦应删除。
- **真实安全约束**：真实禁止规则（如“不得覆盖...”）与事务失败后果无论 Jev 如何判定，必须保留。
- **未覆盖内容**：表格与代码块不在 Jev 逐句扫描范围内，须人工核验。
- **调用异常处理**：若 Jev 调用失败，明确说明未完成自动化判断，继续基于人工事实规则编辑，绝不声称 Jev 已通过。

## 表达与删减规范

- **文字规范**：短句、主动语态、一句话一个要点。中文借鉴 ASD-STE100 清晰表达原则（禁用分号连接复杂句、避免动词名词化）。
- **真实禁止规则保留**：否定句是安全约束的直接表达，必须保留。
- **消除指代与占位**：用项目具体事实替换会话代词（“该方案”、“上文”），清除过期占位符。
- **密度保持**：用户指出一类问题时检查全文；用户认可简洁稿后，后续修订保持该信息密度，不补回已删除说明。

## 校验清单

交付前逐项核对：

1. 文档是否可独立理解，无会话残留和外部代词？
2. 是否已基于代码和配置事实完成查验，消除无依据的推测？
3. 是否已删除所有空章节与仅写“不涉及”的无用段落？
4. Jev 审查报告中指出的跨章节重复与冗余表达是否已核实处理？
5. 接口契约、状态变迁与安全禁止规则是否清晰完备？
6. 全文同类冗余是否已彻底清理，术语前后口径是否完全统一？
