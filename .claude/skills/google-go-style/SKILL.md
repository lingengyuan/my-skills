# Google Go Style

以 [Google Go Style](https://google.github.io/styleguide/go/) 为风格依据，独立处理代码设计与可读性。

## 工作方式

1. 阅读项目要求和相关代码，确定调用方、现有契约与修改范围。
2. 依次考虑清晰性、简单性、简洁性、可维护性和一致性。
3. 按 [主题索引](references/topics.md) 读取本地参考文档的相关章节，结合适用条件与例外作出决策。
4. 优先使用语言内置机制，其次使用标准库。根据实际需求选择抽象和依赖。
5. 按项目要求验证行为，简化实现，删除无用抽象与重复解释。

## 检查项

- **命名与格式**：使用 `gofmt`。名称在调用位置应清楚、简洁。长行优先通过调整结构改善。
- **注释与文档**：说明原因、契约和不明显的行为。
- **错误**：提供有用的上下文。调用方需要检查底层错误时使用 `%w`。明确错误返回和日志责任。
- **接口与包**：围绕实际行为组织代码。通常由使用方定义接口，具体类型提供实现。
- **并发与资源**：明确 goroutine 的停止方式、等待责任和资源清理责任。
- **值与状态**：按语义选择零值、接收器和参数，核对复制、序列化与调用契约。
- **测试代码**：按项目选定的测试方式检查结构和失败信息。

## 输出

交付本次范围内的代码或审查结论。审查结论包含具体位置、实际影响和对应官方章节，并区分行为缺陷、规范性裁决与可选建议。
